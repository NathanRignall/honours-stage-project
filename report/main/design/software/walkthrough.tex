\subsection{Demonstration Walkthrough} \label{sec:demoWalk}

The following configuration walkthrough displays how dynamic software updates are applied to a running system, with example applications.

\lstset{basicstyle=\scriptsize}

\subsubsection{Demonstration Step Zero}

First the initial configuration is loaded which contains a single component $Agent$ with comminations channels to the middleware management fragment.

$Agent$ is an example component that is designed to change the configuration of the system over time. In a real deployment this would be replaced with an application manager that interfaces with a user-facing application.

Channel 1 is used to stop the middleware's operation and shutdown the system and channel 2 is to send the configuration identifiers that the manager should load.

\textbf{Task B - Actions} (\autoref{lst:configDemonstration1b})
 \begin{enumerate}

    \item \textbf{Add Route} - \textit{Blocking} - Create the communication pathway between Edge 1 and $Controller$ (Inbound).
    \item \textbf{Add Route} - \textit{Blocking} - Create the communication pathway between Edge 2 and $Controller$ (Outbound).
    \item \textbf{Set Schedule} - \textit{Blocking} - Modify the schedule so that both $Agent$ and $Controller$ have a time-slice to execute in.
\end{enumerate}

\subsubsection{Demonstration Step Two}

Configuration 2 is the configuration that completes the dynamic software update. A new component first is loaded, its state is synchronised with the old component. When ready, in a single atomic operation all control is passed from the old component to the new component. Finally the old component is cleaned up.

\textbf{Task D - Actions} (\autoref{lst:configDemonstration2d})
 \begin{enumerate}
    \item \textbf{Remove State Sync} - \textit{Blocking} - Remove the state synchronisation between $Controller$ and $Controller^{\prime}$ in the global state.
    \item \textbf{Stop Component} - \textit{Blocking} - Mark the $Controller$ component as not safe to execute in the global state.
    \item \textbf{Remove Route} - \textit{Blocking} - Remove the communication pathway between Edge 1 and $Controller$ (Inbound).
    \item \textbf{Remove Route} - \textit{Blocking} - Remove the communication pathway between Edge 2 and $Controller$ (Outbound).
    \item \textbf{Start Component} - \textit{Blocking} - Mark the $Controller^{\prime}$ component as safe to execute in the global state.
    \item \textbf{Add Route} - \textit{Blocking} - Create the communication pathway between Edge 1 and $Controller^{\prime}$ (Inbound).
    \item \textbf{Add Route} - \textit{Blocking} - Create the communication pathway between Edge 2 and $Controller^{\prime}$ (Outbound).
    \item \textbf{Set Schedule} - \textit{Blocking} - Modify the schedule so that both $Agent$ and $Controller^{\prime}$ have a time-slice to execute in. (Effectively removing $Controller$)
\end{enumerate}
